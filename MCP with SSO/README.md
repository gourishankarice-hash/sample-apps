# PingFederate MCP Server for Microsoft Copilot Studio

A Model Context Protocol (MCP) server that enables OAuth 2.0 and OpenID Connect (OIDC) authentication integration with PingFederate, designed specifically for Microsoft Copilot Studio.

## Overview

This MCP server provides a secure bridge between Microsoft Copilot Studio and PingFederate using HTTP transport. It enables SSO capabilities and token management with a RESTful HTTP API. The server supports both OAuth 2.0 and OIDC flows, allowing Copilot agents to authenticate users and manage their sessions securely.

### Key Features

- **HTTP Transport**: RESTful HTTP API for easy integration (no stdio required)
- **OAuth 2.0 Authorization Code Flow**: Full support for authorization code grant with PKCE-ready implementation
- **OpenID Connect (OIDC)**: Complete OIDC support including ID token validation and user info endpoints
- **Token Management**: Automatic token refresh, caching, and revocation
- **Security**: State parameter validation, CSRF protection, secure token storage
- **Copilot Studio Integration**: Tailored for Microsoft Copilot Studio with proper MCP protocol compliance
- **Configurable**: Easy environment-based configuration for different PingFederate instances

## Architecture

```
Microsoft Copilot Studio
        ↓
   HTTP Client
   (GET/POST to REST API)
        ↓
   HTTP MCP Server (localhost:3000)
   (This Project)
        ↓
  PingFederate
   (OAuth 2.0/OIDC)
        ↓
   User Authentication & Token Management
```

## Installation

1. **Clone or download this project**

   ```bash
   cd "MCP with SSO"
   ```

2. **Install dependencies**

   ```bash
   npm install
   ```

3. **Create environment configuration**

   ```bash
   cp .env.example .env
   ```

4. **Configure PingFederate settings in `.env`**

   ```env
   PING_BASE_URL=https://your-pingfederate.example.com:9031
   PING_CLIENT_ID=your_oauth_client_id
   PING_CLIENT_SECRET=your_oauth_client_secret
   PING_REDIRECT_URI=http://localhost:3000/callback
   PING_TOKEN_ENDPOINT=/as/token.oauth2
   PING_AUTHORIZE_ENDPOINT=/as/authorization.oauth2
   PING_USERINFO_ENDPOINT=/pf-ws/rest/oauth/userinfo
   
   NODE_ENV=development
   TOKEN_CACHE_TTL=3600
   ```

## Configuration

### PingFederate Settings

| Variable | Description | Example |
|----------|-------------|---------|
| `PING_BASE_URL` | Base URL of PingFederate server | `https://pingfed.company.com:9031` |
| `PING_CLIENT_ID` | OAuth 2.0 client ID | `copilot-mcp-client` |
| `PING_CLIENT_SECRET` | OAuth 2.0 client secret | Generated by PingFederate |
| `PING_REDIRECT_URI` | Redirect URI after authentication | `http://localhost:3000/callback` |
| `PING_TOKEN_ENDPOINT` | Token endpoint | `/as/token.oauth2` |
| `PING_AUTHORIZE_ENDPOINT` | Authorization endpoint | `/as/authorization.oauth2` |
| `PING_USERINFO_ENDPOINT` | UserInfo endpoint | `/pf-ws/rest/oauth/userinfo` |

### Server Settings

| Variable | Description | Default |
|----------|-------------|---------|
| `NODE_ENV` | Environment mode | `development` |
| `HTTP_PORT` | HTTP server port | `3000` |
| `HTTP_HOST` | HTTP server host | `localhost` |

## Available Tools

The MCP server exposes the following tools for use in Microsoft Copilot Studio:

### 1. `generate_auth_url`
Generates the PingFederate authorization URL to initiate the OAuth flow.

**Input:**
- `scope` (optional): OAuth scopes (default: `"openid profile email"`)

**Output:**
- `authorization_url`: The URL to redirect users for authentication
- `message`: Confirmation message

**Example Usage:**
```
User: "Authenticate me with PingFederate"
Tool: generate_auth_url
Response: "Here's the login URL..."
```

### 2. `exchange_authorization_code`
Exchanges the authorization code for access and refresh tokens.

**Input:**
- `code` (required): Authorization code from callback
- `state` (required): State parameter from callback

**Output:**
- `access_token`: OAuth access token
- `refresh_token`: Token for refreshing access
- `expires_in`: Token expiration time in seconds
- `scope`: Granted scopes

**Example Usage:**
```
After user authenticates and is redirected:
Tool: exchange_authorization_code
Input: code="abc123", state="xyz789"
Response: Returns tokens for API access
```

### 3. `get_user_info`
Retrieves authenticated user information.

**Input:**
- `access_token` (required): Valid OAuth access token

**Output:**
- `user_info`: Object containing:
  - `sub`: Subject/user ID
  - `email`: User email
  - `name`: Full name
  - `preferred_username`: Username
  - Other OIDC claims

### 4. `refresh_access_token`
Refreshes an expired access token.

**Input:**
- `refresh_token` (required): Refresh token from initial auth

**Output:**
- `access_token`: New access token
- `expires_in`: New expiration time
- `scope`: Granted scopes

### 5. `get_valid_token`
Gets a valid access token, automatically refreshing if necessary.

**Input:**
- `refresh_token` (required): Refresh token

**Output:**
- `access_token`: Valid access token (fresh or cached)
- `message`: Status message

### 6. `revoke_token`
Revokes a token (logout).

**Input:**
- `token` (required): Token to revoke
- `token_type` (optional): `"access_token"` or `"refresh_token"`

**Output:**
- `success`: Confirmation status
- `message`: "Token successfully revoked. User is logged out."

### 7. `decode_id_token`
Decodes and validates ID token claims (OIDC).

**Input:**
- `id_token` (required): JWT ID token

**Output:**
- `claims`: Decoded token claims with user information

### 8. `get_discovery_metadata`
Retrieves OpenID Connect discovery metadata.

**Input:** (none)

**Output:**
- `metadata`: Object containing:
  - Endpoints (authorization, token, userinfo)
  - Supported algorithms and features
  - Public key information

## Integration with Copilot Studio

### Step 1: Start the HTTP Server

```bash
npm start
```

The server will be available at `http://localhost:3000`

### Step 2: Configure Copilot Studio

1. In Copilot Studio, configure the MCP server connection:
   - **Server URL**: `http://localhost:3000`
   - **Tools Endpoint**: `http://localhost:3000/mcp/tools` (GET)
   - **Execute Endpoint**: `http://localhost:3000/mcp/execute` (POST)

2. Set environment variables in Copilot Studio configuration to pass to the server

3. Map the available tools to agent actions

### Step 3: Use in Agent

Create a Copilot agent that uses these tools:

```
Agent Instructions:
- Use "generate_auth_url" to start authentication
- Direct users to the returned authorization URL
- After they authenticate, use "exchange_authorization_code" with the code
- Use "get_user_info" to retrieve user details
- Use "refresh_access_token" to maintain session
- Use "revoke_token" for logout
```

### Testing the Connection

```bash
# Check server health
curl http://localhost:3000/health

# List available tools
curl http://localhost:3000/mcp/tools

# Get server info
curl http://localhost:3000/mcp/info
```

## Security Considerations

### Development vs Production

- **Development**: SSL certificate validation is disabled (`rejectUnauthorized: false`)
- **Production**: Update `src/pingfederate.ts` to enforce SSL verification

### Token Storage

Tokens are cached in-memory with TTL-based expiration. For production:
- Implement secure token storage (encrypted database, vault)
- Add Redis for distributed token caching
- Implement token rotation strategies

### State Parameter Validation

The server implements CSRF protection using state parameters:
- State is generated randomly for each auth session
- State is validated on token exchange
- State expires after 5 minutes
- Old states are periodically cleaned up

### HTTPS Requirement

Always use HTTPS URLs in production:
- `PING_REDIRECT_URI` must be HTTPS
- `PING_BASE_URL` must be HTTPS
- Enforce HSTS headers

## OAuth 2.0 Flow Diagram

```
User/Copilot Studio
        ↓
        1. generate_auth_url
        ↓
    PingFederate
    (Authorization URL)
        ↓
    User Login
        ↓
    Redirect with code
        ↓
        2. exchange_authorization_code
        ↓
    PingFederate (Token Endpoint)
    (Returns access_token, refresh_token)
        ↓
        3. get_user_info / decode_id_token
        ↓
    User authenticated and authorized
```

## Troubleshooting

### Server fails to start with "Address already in use"

**Cause**: Port 3000 is already in use
**Solution**: 
```bash
# Use a different port
HTTP_PORT=3001 npm start

# Or find and kill the process using port 3000
# On Windows:
netstat -ano | findstr :3000
taskkill /PID <PID> /F
```

### Connection refused error from Copilot Studio

**Cause**: Server is not running or not accessible
**Solution**:
```bash
# Check if server is running
curl http://localhost:3000/health

# If not running, start it
npm start

# If running but Copilot Studio can't reach it, check firewall
# For production, use HTTPS and proper networking
```

### "Missing required PingFederate configuration"

**Cause**: Environment variables not set
**Solution**: Create `.env` file with all required variables (see Configuration section)

### "Invalid or expired state parameter"

**Cause**: State was not generated by this server or has expired
**Solution**: Generate a new auth URL and start fresh

## Deployment

### Local Testing

```bash
npm run build
npm start

# Server runs on http://localhost:3000
```

### Docker

Create `Dockerfile`:

```dockerfile
FROM node:18-alpine

WORKDIR /app

COPY package*.json ./
RUN npm ci --only=production

COPY dist ./dist

ENV NODE_ENV=production
ENV HTTP_PORT=3000
ENV HTTP_HOST=0.0.0.0

EXPOSE 3000

CMD ["node", "dist/server.js"]
```

Build and run:

```bash
docker build -t pingfederate-mcp:latest .
docker run -p 3000:3000 \
  -e PING_BASE_URL=https://... \
  -e PING_CLIENT_ID=... \
  -e PING_CLIENT_SECRET=... \
  -e PING_REDIRECT_URI=... \
  -e PING_TOKEN_ENDPOINT=/as/token.oauth2 \
  -e PING_AUTHORIZE_ENDPOINT=/as/authorization.oauth2 \
  -e PING_USERINFO_ENDPOINT=/pf-ws/rest/oauth/userinfo \
  pingfederate-mcp:latest
```

### Azure / Cloud Deployment

1. Build: `npm run build`
2. Deploy `dist/` folder to your cloud platform
3. Set environment variables in cloud configuration:
   - `HTTP_PORT` (usually 3000 or 8080)
   - `HTTP_HOST` (0.0.0.0 for cloud)
   - All `PING_*` variables
4. Ensure outbound HTTPS access to PingFederate
5. Use HTTPS/TLS for the HTTP server in production
